# AgentPack — Build PlanE**Audience: an autonomous coding agent (e.g. Claude Code) executing this build.**ERead this whole file before writing code. Work phase by phase, in order. Do not skip ahead. After each phase, verify against its "Definition of done" before moving on. Do not add anything listed under "Explicitly out of scope."EE---EE## 0. What this project isEEAgentPack packages a personal AI agent's **entire setup** — system prompt, MCP tool refs, skills, permission scopes, memory config — into one versioned, runnable manifest (`agentpack.yaml`), plus a CLI to build, run, and share it.EE**Refinement over the original idea:** this project is *agent-native by design*, not just human-tooling. Inspired by kado.so (a search/discovery service meant to be installed and called by a Personal Agent, with agent-facing docs like `llms.txt`), every part of AgentPack must be equally usable by:E1. A human developer, via the CLI and normal README.E2. A Personal Agent, which should be able to discover, install, and use AgentPack — and reason about a specific published manifest — without a human walking it through anything.EEConcretely this means: an `llms.txt` at the project root, an `AGENT.md` alongside every published manifest describing it in agent-readable terms, and CLI output/errors written to be parsed by an agent, not just read by a human.EE---EE## 1. ScopeEE### In scope (v1)E- Manifest spec: `agentpack.yaml` — identity, model, prompt, tools, skills, permissions, memory.E- CLI (`agentpack`): `init`, `run`, `pull`, `push`, `diff`.E- One target harness: **Claude Code**.E- Sandboxing via plain Docker (shell out to the Docker CLI/SDK — do not build a custom runtime).E- Registry v1: a GitHub repo acting as an index (one file per published agent, pointing to source repo + pinned commit).E- Agent-native layer: `llms.txt`, per-manifest `AGENT.md`, structured (JSON-capable) CLI output.EE### Explicitly out of scope (do not build these — ask before adding)E- Payments / x402 / any agent-to-agent transaction logic.E- Behavioral trust scoring, static+LLM+sandbox verification pipelines.E- Multi-harness abstraction (LangGraph, AutoGen, custom loops).E- A hosted registry backend, auth system, or web UI.E- Multi-agent orchestration / "compose" for agent teams.E- A live search/discovery service like Kado's — v1's registry is a static, browsable index, not a query API. Note this as a clearly separated future phase if it comes up; do not start it now.EE---EE## 2.
